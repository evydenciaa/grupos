# Plesk compartilhado
Verificar PHP CLI/web 8.3+, extensões intl, mbstring, pdo_mysql, curl, fileinfo, openssl, zip; Composer 2, limites de CPU/memória/disco e PHP upload/post. Preferir 8.4. Não expor .env, vendor, storage privado ou git. Document root deve ser public/; APP_DEBUG=false, APP_URL HTTPS, chave estável; banco utf8mb4 InnoDB e usuário de privilégio mínimo. Backup antes de migrate --force. composer install --no-dev --optimize-autoloader a partir do lock; php artisan optimize; storage:link apenas após revisão dos arquivos públicos. Sem Node/FFmpeg em produção.
Scheduled Tasks: executar script PHP artisan com argumento schedule:run, mesma versão PHP do site, frequência mínima confirmada no painel. Se cron mínimo 5 minutos, projetar comandos para janela e não depender de minuto exato. Cache database, sessões file, sem workers contínuos. Manutenção somente, não ativar envio automático. Documentação: https://docs.plesk.com/en-US/obsidian/customer-guide/scheduling-tasks.65207/

## Atualização de contagens
Execute php artisan grupos:refresh-metadata para atualizar no máximo um grupo pendente por chamada. Após confirmar cron, tempo de resposta e cache database, é possível habilitar GRUPOS_METADATA_AUTO_REFRESH=true no .env e executar php artisan config:cache. O scheduler tenta a cada cinco minutos; cada grupo elegível é revisitado após 24h e falhas entram em espera de uma hora. Instâncias precisam ter lista sincronizada nos últimos sete dias. Não há envio neste comando. Não habilite antes de confirmar os limites da revenda e da API. Para primeira carga, use ação de sincronização da instância e o comando de metadados; links são obtidos sob demanda. Se o Plesk não roda schedule:run regularmente, execute o comando diretamente na tarefa PHP.
